# 性能问题修复与复测

本次修改针对[修复前实测](performance-review.zh-CN.md)发现的单桶轮询、借出 PING 和闲置状态保留问题。

## 修改

- 有额度但还没轮到当前客户端时，等待提示改为按有效速率计算的 1–50ms；低配额仍按令牌/窗口实际等待时间重试。FIFO 顺序、原子扣费和窗口上限不变。
- 工厂连接池默认关闭 `testOnBorrow`，改为空闲校验；可通过 `.redisTestOnBorrow(true)` 恢复借出校验。连接失败仍拒绝申请，不自动重试可能已经扣费的操作。
- Redis 桶、窗口和队列按安全期限自动回收。最短闲置保留期默认 60 秒，可以配置；实际保留期不能短于完整补桶、窗口、回执与租约期限。活跃访问一起续期，多客户端使用不同保留期时保留最长安全期限，时钟回拨时额外延长。
- 明确 `redisTimeoutMs` 是各阶段超时，不是整个调用的硬 deadline。取消 PING 消除了额外的校验请求；连接池拥塞、建连或脚本重载时，总耗时仍可能超过该参数，不能承诺每次 200ms 内返回。

Redis key 协议更新为 **v4**。旧客户端不会续期新 TTL，因此不能在旧 key 上直接开启回收。升级时必须停止旧客户端、排空已发请求并等待旧配额恢复，再统一切换；不能让 v3/v4 同时为同一受限业务发额度。详见[迁移步骤](reference.zh-CN.md#从旧-snapshot-升级)。

## 重启期间的 LOADING 修复

首轮 180 秒故障复测出现 58 次 ERROR，未通过断言。用原 AOF 单独重放时复现了 `LOADING Redis is loading the dataset in memory`：Redis 已接收连接但尚未完成数据恢复。客户端现将明确的 LOADING 响应归入临时不可用，默认返回 WAIT/DENY；其他 Redis 数据和脚本错误仍为 ERROR。故障测试保留零 ERROR 断言，并额外保存失败时的采样、故障时间和错误详情。

## 回归覆盖

新增单元和真实 Redis 回归：高配额快速重试保持 FIFO、低配额不忙轮询、窗口/补桶/回执期限保护、闲置队列回收、登记续期、不同客户端保留期、时钟回拨保护。加上既有用例，新增 LOADING 回归后，共 147 项测试。

压测仍采用本机 Java 21、Redis 8.0.2，每轮预热 3 秒、测量 10 秒，两轮反向运行。压测客户端改用公共工厂创建连接池，并保留开启借出校验的对照组。专门增加 5,000 资源的回收断言。30 JVM 故障场景使用当前默认连接策略；CI 新增 90 秒故障回归，不设机器相关的吞吐门槛。

这些是本机短期复测，不能据此推断生产容量、长期泄漏或 Redis 故障转移安全性。

## 本机吞吐对比

两轮数据范围，单位为成功发放次数/秒。不是全部调用 QPS，WAIT 不计作成功。

| 场景 | v3 基线 | v4 修复后 |
|---|---:|---:|
| 单线程普通令牌桶 | 3,823.5–4,225.3 | 3,904.3–3,934.3 |
| 单线程滑动窗口 | 4,108.2–4,228.2 | 3,968.2–3,998.4 |
| 30 客户端单桶，按提示重试，开启借出校验 | 35.8–36.2 | 808.7–863.0 |
| 30 客户端单桶，各版默认连接策略 | 35.8–36.2 | 1,121.0–1,149.9 |
| 30 线程 / 100 桶，各版默认连接策略 | 15,348.1–15,873.9 | 19,962.4–21,037.2 |
| 30 线程 / 100 桶，都开启借出校验 | 15,348.1–15,873.9 | 13,414.5–15,000.2 |

同样开启借出校验的单桶对照提升约 22–24 倍；结合新的默认连接策略提升约 31–32 倍。高配额单桶的获取调用量也由约 589/s 增至 12,868–13,767/s，这是缩短轮询的成本，不能描述为无成本提速。低配额依然按实际预算等待，由独立故障场景继续验证。

开启借出校验的多桶对照略慢于基线：安全回收增加了 Redis 状态更新，加上共享机器波动，不能声称所有负载都更快。默认策略下的多桶有效吞吐则提升到约 2 万/s。单桶严格 FIFO 仍由 Redis 串行处理和客户端轮询推进，不应把配置的高配额等同于可达吞吐。

5,000 资源回收案例两轮均通过：将最短闲置期配置为 1 秒，实际安全保留期仍不短于 5 秒等待租约，停止访问 7 秒后 Redis key 数为 **0**，用量约 1.26 MiB。普通案例保持默认 60 秒最短保留期，停止 5 秒时仍有状态，这是预期行为。

18 轮性能测试均为零 ERROR、零 Redis 故障拒绝。原始每轮数据由 `load_test.py` 输出到 `target/load-*/`；短期故障场景与兼容性结果在对应 PR/CI 中保留。
